# QueueNow V1 Acceptance Criteria

## Product

- [ ] Customer can open QR link without account.
- [ ] Customer sees queue open/paused/closed state.
- [ ] Customer can join an OPEN queue.
- [ ] Queue number is generated by server.
- [ ] Customer sees people ahead and return window.
- [ ] Customer can set Away/Nearby/Returned.
- [ ] Customer can cancel own eligible ticket.
- [ ] Merchant can add manual walk-in.
- [ ] Merchant can Call Next.
- [ ] Merchant can Start, Complete, Skip, Recall.
- [ ] Grace/late state is visible and recoverable.
- [ ] Public display updates with sanitized data.
- [ ] Queue history shows terminal tickets.

## Correctness

- [ ] 50 concurrent unique joins create 50 unique sequence numbers.
- [ ] Repeated identical join ID with the correct recovery secret returns the same ticket without consuming another number.
- [ ] Join ID alone cannot recover a ticket capability; wrong recovery proof fails without mutation or ticket data.
- [x] Concurrent Call Next cannot select the same ticket twice in the internal Durable Object runtime test.
- [ ] Duplicate command ID is not executed twice.
- [ ] Illegal lifecycle transitions fail without mutation.
- [ ] Queue revision is monotonic.
- [ ] DO restart reconstructs state.
- [ ] D1 projection failure does not undo completed authoritative command.

## Security

- [ ] Queue number alone cannot read/control private ticket.
- [ ] Customer capability cannot control another ticket.
- [ ] Merchant command requires valid authorization.
- [ ] Staff cannot operate another shop without permission.
- [ ] Cookie-auth mutation CSRF defense passes.
- [ ] Login/join abuse controls exist.
- [ ] Display stream contains no secret/private fields.
- [ ] Logs redact authorization, session, ticket-capability, and join-recovery secrets.
- [ ] Frontend bundle contains no production secret.

## Realtime

- [ ] Customer receives called update without polling.
- [ ] Merchant boards synchronize.
- [ ] Display synchronizes.
- [ ] WebSocket reconnect succeeds.
- [ ] Revision gap forces authoritative recovery.
- [ ] Disconnected UI does not look live.

## Offline

- [ ] Static shell can load according to cache policy.
- [ ] Last safe snapshot can be displayed as stale if implemented.
- [ ] Join is blocked offline.
- [ ] Merchant queue mutations are blocked offline.
- [ ] Customer cancel/presence mutation is blocked offline.
- [ ] No service-worker background replay of authoritative mutations.

## PWA

- [ ] Valid manifest/icons.
- [ ] Merchant install path works on supported browsers.
- [ ] Safe-area handling verified.
- [ ] No horizontal overflow at target viewports.
- [ ] Explicit update available UI.
- [ ] Update Now / Later.
- [ ] Version/build ID visible.
- [ ] No silent forced update during active operation.
- [ ] Accessibility regression checks pass.

## CI/CD

- [ ] PR runs lint/typecheck/tests/build.
- [ ] State-machine tests required.
- [ ] Concurrency tests required.
- [ ] Playwright core flow required.
- [ ] CodeQL/dependency checks configured.
- [ ] Production secrets unavailable to fork PR.
- [ ] Main deploy records commit SHA.
- [ ] Production smoke/readback runs.

## Pilot

- [ ] One business-day simulation passes.
- [ ] Operator runbook exists.
- [ ] Quota usage measured.
- [ ] Failure/reconnect drill passes.
- [ ] Known limitations documented.
- [ ] Release evidence references exact commit/deployment.

V1 may be marked production-pilot-ready only when every P0 criterion is evidenced, not merely planned.
